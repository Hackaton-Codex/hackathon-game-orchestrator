# RPG web prototyping

Use this skill for a browser RPG built with HTML, CSS, and plain JavaScript. First inspect the existing project and preserve its structure. If none exists, do not initialize it until the user has chosen the stack and any relevant event rules permit advance work.

## Authorization and scope

- If the event's rule on advance work is unknown, limit work to concepts, planning, and reusable process guidance. Do not create game code, assets, or a project scaffold until the rule is confirmed.
- Once implementation is allowed, build a small playable scene first. Keep the project easy to open or reconstruct in a browser and expand only after that slice works.
- Use real specialist agents only when available, with tasks scoped to distinct deliverables. Never claim delegation that did not happen.

## Narrative RPG decisions

- Keep chapter, step, missions, evidence, human subplots, and attributes in a clear state model; make UI reflect state changes immediately.
- Prioritize exploration, readable dialogue, meaningful choices, and observable consequences. Keep on-screen text short and put longer records in a journal.
- When the user chooses a Chilean setting with fictional cases, make people, companies, incidents, and violations fictional. Do not present narrative outcomes as legal advice or claims about real organizations.
- Use original characters and assets. A requested mood or genre reference is guidance, not permission to copy protected characters, art, audio, or branding.
- Track author, source, license, and modifications for third-party assets; document the code license separately.

## Delivery

When implementation is authorized, provide clear controls, objective, and browser run instructions. Preserve a playable route through the scene and explain any requirements to rebuild it. Run tests or additional verification when the user requests them.
